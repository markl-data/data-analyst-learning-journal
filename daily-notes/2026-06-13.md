# 2026-06-13 - Day 10: Window Functions Introduction

## The Conceptual Shift
GROUP BY collapses rows and gives the aggregate.
Window functions preserve rows and give the aggregate alongside.

## What clicked today
- Window functions finally felt natural — especially the pattern of “partition, order, then filter”.

- Ranking logic became intuitive. Could see when to use RANK() vs ROW_NUMBER() without hesitation.

- Scalar subqueries clicked as a clean way to pull in company‑wide totals without needing a CTE.

- Recognized syntax issues instantly (like alias mismatches), which means my debugging instincts are sharpening.

## What is still effortful
- Formatting output - understanding that alignment is a UI behavior, not SQL, and knowing when to cast/format to control presentation.

- Multi‑layer window logic - combining multiple window functions and a scalar subquery in one SELECT still takes deliberate thought.

- Self‑joins on ranked data - the pattern works, but still need to slow down to avoid alias mistakes.

- Remembering exact syntax - especially when switching between rnk, rank, and function names.

## Patterns I've banked
- Top N per group (rank + filter)
- Running totals
- Each row alongside group benchmark
